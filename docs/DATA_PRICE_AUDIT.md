## Decision: `is_price_reliable` flag (not deletion, not clamping)

The 20-lowest-priced table above tells the real story: every one of them is
**exactly $0.00** for both `price_low` and `price_high` - not a low price,
a sentinel. A direct count confirms this is a hard cliff, not a
continuum: **961 rows have price = $0.00 exactly, and zero rows fall
between $0 and $500.** A handful (35 rows) sit between $500 and $2,000 -
those are genuine, if very low, valuations for old/high-mileage vehicles
(e.g. a 2007 Chevrolet Cobalt at 180,000 miles, $1,480) and are **not**
flagged.

**Threshold: `is_price_reliable = false` if and only if `price == 0`**
(equivalently `price_low == 0 AND price_high == 0`, confirmed by the empty
$0-$500 gap above). Justification:
- A real used car is never actually worth $0 - this is KBB's "no valuation
  available" sentinel leaking through as a numeric zero instead of NULL,
  most concentrated in brand-new/future model years (2026: 127 rows,
  2027: 270 rows - vehicles too new to have an established resale value)
  but present across all eras (1987-2025: 564 rows), so it is not purely a
  "too new" artifact.
- The wide-range rows (6 found, `price_high / price_low > 3x`) are **not**
  flagged: their absolute dollar spread is modest ($600-$3,850 total range)
  and all are old, very-high-mileage vehicles (169k-344k miles) where wide
  valuation uncertainty is itself plausible, not erroneous.
- Per CLAUDE.md's Data Honesty principle and this task's explicit
  instruction: the 961 rows are **flagged, not deleted or clamped** to some
  floor price. `vehicles.price` still literally contains `0.00` for them;
  `is_price_reliable=false` is the signal every consumer must check.
  `data/scripts/clean_listings.py::compute_price()` computes this flag at
  ETL time; `src/dealership_agent/retrieval/search.py::search_listings()`
  excludes `is_price_reliable=false` rows whenever a price filter is
  active (same policy as NULL price) and masks `price`/`price_low`/
  `price_high` to `None` in every result, filtered or not, so nothing
  downstream can mistake the sentinel for a real price.

## Note: semantic similarity does not encode price relativity

Vector search ranks by how semantically similar a description is to the
query text - it has no notion that $8,000 is "cheap" and $80,000 is not.
Embedding the word "cheap" into a query does **not** bias the result set
toward cheap vehicles; it biases toward listings whose *text* uses similar
language (e.g. "affordable", "great value", "priced to sell"), which
correlates only loosely and unreliably with actual price. A query like
"cheap reliable family SUV" must therefore have "cheap" translated into an
explicit `price_max` **before** it reaches `search_listings()` - the
embedding model must never be trusted to do this translation implicitly.
This is why the agent's router (Part C) derives concrete numeric filters
from the `is_price_reliable=true` distribution above (p25=$18,050 as a
"cheap" ceiling, p75=$40,956.75 as a "premium" floor - see
`src/dealership_agent/agents/router.py`) rather than leaving price
language for the embedding to "understand" on its own.
