# dealership-agent: Project Constitution

This file is the project constitution. Read it and obey it in every session.
Anything under "locked" or "invariant" below must not be changed without
explicitly asking the user first.

## Architecture Decisions (locked, do not change without asking)

- Modular monolith. ONE FastAPI service. No microservices.
- NO Kubernetes. Deployment target is AWS ECS Fargate.
- Multi-agent: one Supervisor + two sub-agents, split by TOOL PERMISSION SCOPE:
  - Sales Agent (read-only, public data): `search_listings`, `search_policy_docs`
  - Account Agent (customer-scoped): `get_order_status`, `list_my_orders`,
    `escalate_to_human`

  The split IS the security boundary. Sales Agent must never have order tools
  bound.
- Orchestration: LangGraph.
- Database: PostgreSQL with pgvector. ONE database. No separate vector store.
- Embeddings: sentence-transformers, self-hosted, IDENTICAL in dev and prod.
  Never use a cloud embedding API.
- LLM: provider interface with two implementations, Groq (local dev) and
  AWS Bedrock (prod). Per-node model routing: cheap model for
  classification/guardrails, stronger model for final synthesis.
- Observability: self-hosted Langfuse.
- IaC: Terraform. CI: GitHub Actions with OIDC, no long-lived AWS keys.
- Tools are exposed via an MCP server (framework-independent tool layer). The
  LangGraph agent consumes them as a real MCP client over stdio, one
  subprocess per conversation turn. Identity injection and authorization
  happen at the MCP server boundary.
  - Dependency: `mcp`. `langchain-mcp-adapters` remains declared in
    `pyproject.toml` but is not imported anywhere in `src/` as of ADR 0004;
    see `docs/adr/0003-mcp-client-in-process-bridge.md` and
    `docs/adr/0004-mcp-identity-propagation.md` for why.

## The Core Security Invariant (highest priority rule in this codebase)

The LLM must NEVER be able to choose whose data it reads.

- Identity is authenticated at the FastAPI edge via JWT, before the agent runs.
- The Session object lives in LangGraph state, NEVER in any prompt, message,
  system instruction, or tool schema exposed to the model.
- Tool signatures visible to the LLM must NOT contain `customer_id`,
  `tenant_id`, `user_id` or any identity parameter. Tools take only
  non-identity args like `order_ref`.
- The customer scope is injected server-side at tool execution time (at the
  MCP server boundary).
- Defence in depth: PostgreSQL Row-Level Security enforces the same
  constraint at the data layer.

If you are ever about to add an identity field to a tool schema, STOP and ask.

## Engineering Standards

- Python 3.12. Type hints everywhere, mypy strict.
- Ruff for lint and format.
- Pydantic v2 for all boundaries (API, tool args, config).
- pytest. Every tool gets unit tests. Every graph path gets an integration
  test.
- No Jupyter notebooks in this repo. Ever.
- No secrets in code or git. Config via pydantic-settings and environment
  variables.
- Structured JSON logging. No print statements.
- Conventional Commits format for all commit messages.

## Anti-Over-Engineering Rules

Do not add: message queues, Kubernetes, microservices, a custom auth service,
a separate vector database, fine-tuning, or a third agent.

If you think one is needed, ask first and justify it.

## Data Honesty

Car listings are real market data from a public dataset. The transactional
layer (orders, customers, bookings) is SYNTHETIC, generated by a seeded
reproducible script. Policy documents are hand-authored.

This must be stated plainly in README.md. Never obscure it.
